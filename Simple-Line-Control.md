# Direct three-sensor line control

Requested 2026-11-18: remove the defensive corner/recovery logic after real runs were slow and missed more turns.

## Design

Use the current normalized L/C/R tape readings directly. Centre-only commands equal forward wheel speeds. Left+centre and right+centre reduce the inside wheel to the capture setting; an outer-only reading releases that wheel and drives the outside wheel at correction speed. No tape continues an arc toward the last unambiguous side at turn speed, or straight if no side is known. Both outer sensors/all three command straight travel because they do not identify a unique side. Fresh readings take effect immediately.

This replaces geometric corner prediction, incoming-strip rejection, approach travel, bounded sweeps, recovery episodes, the centre-confirmation slowdown latch and coast-before-steering. No reverse wheel commands are generated by line following. Keep encoder wheel-speed regulation, explicit Stop, control-connection expiry and encoder fault detection. Line mode still starts only on tape unless the explicit battery auto-start mode is selected.

Alternatives considered: retaining and tuning the geometric controller would retain the complexity the user rejected. Direct PWM would also remove wheel-speed regulation and change the existing tuning interface; that is unnecessary for simplifying sensor decisions. Use direct sensor steering with the existing wheel regulator.

Initial eight-cell targets: straight 250 mm/s, lost-line outer wheel 250 mm/s, correction outer wheel 250 mm/s, gentle-correction inner wheel 125 mm/s. Motor feed-forward values remain estimates. No floor-performance claim follows from host tests. With no tape, the simple controller continues its remembered arc until new tape or Stop; it cannot distinguish a gap from the end of a line.

## Verification and deployment status

The new direct-policy test failed against the old controller and passes against this implementation. The UNO R4 WiFi build passes (144596 bytes flash, 20016 bytes global RAM). The full suite is **not green**: `test_line_control_replay` and `test_line_eight_cell` fail their nominal 135-degree bend, and `test_line_eight_cell_course` detects an extra rotation in the long-coast/encoder-error variant. These outcome assertions were not weakened. The tests also contain old end-of-line search/stop expectations which no longer describe this policy.

The previous course model passes with the simple policy, but that is not physical validation. The sensor rules, immediate correction/centre release, battery startup, Stop, Wi-Fi ownership/expiry, and transport checks pass. A fresh code review found no blocking integration defect; it identified the changed capture-field meaning, now documented. Do not infer reliability from the unit-test results.

The initial simplification was not uploaded at that stage. The subsequent `direct-live-v1` build, including this follower plus Wi-Fi sliders and live path telemetry, was uploaded on 2026-11-18 after the user connected USB. Serial verification reported `WIFI_READY` with that build identifier and `MANUAL,STOPPED` with zero outputs. Forward-only direct steering is implemented as requested, but its acute-turn limitation remains unresolved. A temporary comparison with pivot-on-lost-tape also failed the 135-degree model, so it was not substituted or uploaded.
